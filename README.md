# Winter Dev Pack

Это стартовый набор для нового веб-проекта. В нём есть небольшая демонстрационная страница, чтобы сразу проверить сборку: шапка, основной блок, карточки и футер. Замените или удалите эти примеры, когда начнёте свой проект.

## Если вы хотите просто посмотреть сайт

### Первый запуск

1. Установите Node.js. На странице загрузки выберите версию **LTS** и установите её с обычными настройками: [nodejs.org](https://nodejs.org/en/download).
2. Откройте папку `winter_dev_kit` в Visual Studio Code.
3. В верхнем меню выберите **Терминал → Создать терминал**.
4. В открывшемся окне один раз выполните:

    ```text
    npm install
    ```

    Это установит нужные инструменты и автоматически создаст папку `build`. Для установки нужен интернет.

5. Чтобы открыть сайт и начать работу, выполните:

    ```text
    npm start
    ```

Браузер откроется сам. Пока вы работаете, оставьте окно терминала открытым. Сохраните файл в папке `src` — страница пересоберётся и обновится автоматически.

Чтобы остановить сайт, нажмите **Ctrl+C** в окне терминала.

Если браузер не открылся, найдите в терминале строку **«Локальный сервер»** и скопируйте адрес из неё в браузер. Если стандартный порт уже занят, проект сам выберет другой и покажет новый адрес.

## Как поменять обычный текст

Большинство текстов главной страницы находится в файле `src/data.json`. Откройте его в редакторе и замените текст между кавычками:

- `projectName` — название в шапке;
- `pageTitle` — большой заголовок на баннере;
- `pageDescription` — текст под заголовком;
- `shareTitle` и `shareDescription` — подписи, которые увидят люди при отправке ссылки в мессенджере.

Не удаляйте кавычки и запятые вокруг текста. Например:

```json
{
	"pageTitle": "Стартовый набор для веб-разработки"
}
```

Сохраните файл — при запущенном `npm start` браузер обновится сам.

## Как добавить или изменить карточки

Карточки на главной странице берут текст из списка `items` в `src/data.json`. Каждая карточка состоит из заголовка и описания:

```json
{
	"title": "Моя новая карточка",
	"description": "Коротко расскажите, что она показывает."
}
```

Чтобы добавить карточку, скопируйте один такой блок внутрь списка `items`, поменяйте два текста и проверьте запятые между блоками. Если вы меняете только слова, файл `src/components/feature-card.njk` трогать не нужно: он отвечает за внешний вид каждой карточки.

## Где менять ссылки и картинки

- Ссылки на ВКонтакте и Telegram находятся в `src/components/footer.njk`. В адресе после `href=` укажите нужную страницу, а между тегами замените текст ссылки.
- Большой зимний баннер находится в `src/assets/social-banner.png`. Он же используется для предпросмотра ссылки в мессенджерах. Если замените картинку, оставьте это имя файла или обновите путь в стилях и `src/data.json`.
- Фавиконка — маленькая иконка вкладки браузера — находится в `src/assets/favicon.svg`.
- Адрес сайта и адрес картинки для предпросмотра указаны в `src/data.json` в полях `canonicalUrl` и `shareImageUrl`. Если проект будет опубликован по другому адресу, замените их на новый адрес.

## Что где находится

- `src/pages/` — страницы сайта. Сейчас здесь главная страница.
- `src/components/` — части страницы: шапка, основное содержимое, карточка, футер и кнопки.
- `src/data.json` — тексты и список карточек.
- `src/styles/blocks/` — оформление отдельных частей сайта. Например, `hero.styl` управляет баннером и текстом на нём.
- `src/styles/partials/` — общие настройки: цвета, шрифты, базовые правила и раскладка.
- `src/js/` — JavaScript-файлы. Они добавляют поведение, например обработку кнопок.
- `src/assets/` — картинки и другие файлы сайта.
- `src/fonts/` — файлы шрифтов.
- `build/` — готовая версия сайта, созданная автоматически.

Файлы с окончанием `.njk` — это HTML-шаблоны. Они позволяют собрать страницу из отдельных компонентов и повторять карточку для каждого пункта в списке. Классы стилей написаны по БЭМ: например, `footer` — блок, а `footer__link` — его часть.

Стили написаны на Stylus с фигурными скобками, двоеточиями и точками с запятой. Вложенные элементы блока записываются через `&`, например `.header { &__brand { ... } }`. Основные размеры интерфейса заданы в пикселях. Палитра находится в `src/styles/partials/variable.styl`.

## Как добавить новый шрифт

Файлы шрифтов хранятся в папке **src/fonts**. Создайте в ней отдельную папку для семейства, например **src/fonts/Inter**.

Для каждого начертания используйте одинаковое имя файла и разные расширения. Основной формат — WOFF2 (.woff2): он компактный и подходит современным браузерам. Рядом положите WOFF (.woff) как запасной формат для более старых браузеров. При наличии можно добавить TTF (.ttf), EOT (.eot) и SVG (.svg) для старых систем. Например:

```text
src/fonts/Inter/Inter-Regular.woff2
src/fonts/Inter/Inter-Regular.woff
src/fonts/Inter/Inter-Regular.ttf
src/fonts/Inter/Inter-Regular.eot
```

Откройте **src/styles/partials/fonts.styl** и добавьте строку для каждого начертания. В строке укажите семейство, путь и толщину. Расширение файла писать не нужно: миксин сам проверяет WOFF2, WOFF и запасные форматы.

```text
webfont('Inter', 'Inter/Inter-Regular', 400);
webfont('Inter', 'Inter/Inter-SemiBold', 600);
```

Название и путь в настройке должны совпадать с папкой и именем файла до расширения. Число в конце задаёт толщину: 300 — Light, 400 — Regular, 500 — Medium, 600 — SemiBold, 700 — Bold. Чтобы сделать это семейство основным, поменяйте переменную $font в **src/styles/partials/variable.styl**, например на 'Inter', Arial, Helvetica, sans-serif.

Сохраните файлы и проверьте папку **build/fonts/Inter** после автоматической сборки. Если шрифт не появился на странице, проверьте имя файла, запись в fonts.styl и вкладку Network в инструментах браузера на ошибки 404. Для готовой версии выполните npm run build. Используйте только шрифты, лицензию которых разрешено включать в проект.

## Сборка и готовый сайт

Обычно для работы достаточно команды `npm start`. Если нужно только заново создать готовые файлы, выполните:

```text
npm run build
```

Результат появится в `build/`. CSS сохраняется в читаемой и сжатой версиях. JavaScript-модули собираются в один обычный `build/js/app.js` с относительным путём на странице. Поэтому `build/index.html` можно открыть прямо из папки, без локального сервера.

Не редактируйте файлы в `build/` вручную: при следующей сборке папка создаётся заново. Меняйте файлы в `src/`, а затем снова запускайте сборку.

Если нужно привести код к единому форматированию, выполните `npm run format`. Для автоматического форматирования Stylus при сохранении в Visual Studio Code нужна установленная поддержка Stylus Supremacy.

## Если что-то пошло не так

- **Команда `npm` не найдена.** Установите Node.js по ссылке выше, закройте и снова откройте Visual Studio Code.
- **Страница не обновилась.** Проверьте, что окно с `npm start` всё ещё открыто, и что вы меняете файлы в `src/`, а не в `build/`.
- **Появилась ошибка сборки.** В сообщении найдите имя файла и номер строки. Частая причина при правке `data.json` — пропущенная запятая или кавычка. Исправьте ошибку и сохраните файл.
- **Браузер не открылся сам.** Откройте вручную адрес, напечатанный в терминале после слов **«Локальный сервер»**.

## Если понадобится добавлять программное поведение

Основной JavaScript-файл — `src/js/app.js`. Он импортирует стартовый модуль из `src/js/app/example-module.js`, а также универсальные модули вкладок и появления элементов. Для нового поведения создайте отдельный файл, экспортируйте функцию и импортируйте её в `app.js`: сборщик сам найдёт зависимости. Стартовая страница не использует вкладки и анимацию, поэтому эти модули ничего не меняют без соответствующей разметки. Подробности — в `src/js/README.md`.
